# AGENTS.md — інструкції для Claude / AI-асистентів

Читай цей файл перед будь-якою роботою в репозиторії.

## Що ми робимо
Хакатон, тема **Harmonization of MODIS and VIIRS Hot Spots**. Дедлайн ~15.11.2026.
Веб-додаток, що узгоджує активні осередки пожеж MODIS і VIIRS (NASA FIRMS) у
**календар активності горіння** для вибраної зони інтересу: історичні патерни,
незвичайні умови (аномалії), критичні періоди. Користувачі — служби раннього
попередження, вчені, землекористувачі. Регіон за замовчуванням — Україна.

## Команда
- Toksa — лідер, фронт/бек (досвід з БД і беком).
- Макс — допомагає з фронтом/беком.
- Даня — тестування (`tests/`).
- Ваня, Назар — збір і аналіз даних (`data/`).
Рівень Python у команді — базовий. Пиши простий, читабельний код з коментарями
УКРАЇНСЬКОЮ. Пояснюй рішення так, щоб команда могла захистити їх перед журі.

## Стек і структура
Python 3.11+, Streamlit (UI), pandas, plotly. Без окремої БД — дані з CSV, кеш у parquet.
```
app.py                 Streamlit-додаток (усі вкладки)
firecal/load.py        CSV FIRMS -> єдина схема (lat, lon, date, sensor, conf_class, ...)
firecal/harmonize.py   гармонізація: сітка -> пожежо-клітинко-дні -> union -> калібрування k
firecal/analytics.py   календар, норма, аномалії (робастний z), критичні періоди
firecal/regions.py     зони інтересу (bbox)
scripts/               генератор тестових даних, smoke-тест додатку
tests/                 pytest
data/raw/              сирі CSV (не в git)
```

## Методика (не ламай без обговорення)
1. Достовірність: MODIS <30 low, 30–79 nominal, ≥80 high; VIIRS l/n/h. Лишаємо `type == 0`.
2. Точки -> клітинки сітки (дефолт 0.1°). Одиниця — пожежо-клітинко-день.
3. Union MODIS ∪ VIIRS для періоду з VIIRS.
4. До VIIRS (до 2012): MODIS × k[місяць], k = union/MODIS у період перекриття.

## Правила роботи для AI-агентів

Цей файл лежить у git навмисно: над проєктом працюють кілька людей з різних комп'ютерів,
і правила мусять їхати разом із кодом. Прочитай його першим, перш ніж щось міняти.

**Хто вирішує.** «Людина» нижче — той, хто зараз веде сесію з агентом. Дозвіл, даний
однією людиною, не поширюється на інших, на інші задачі чи на наступну сесію.

### Спільна робота
- **Перед роботою — `git pull`** і погляд на `git status`: хтось міг змінити ту саму частину.
- **Робота — у своїй гілці**, не в `master`. Назва гілки — про суть задачі.
- **У `master` — лише через PR.** Злиття вирішує людина (або рецензент за правилами команди),
  агент сам не мерджить. Маленькі PR, щоб не конфліктувати.
- **Чужі зміни не чіпати**: не відкочувати, не переписувати й не «прибирати» чужий код
  без прохання людини. Конфлікт при злитті — показати людині, а не розв'язувати навмання.
- **Без `push --force`** у спільні гілки, без переписування історії, яку вже хтось стягнув.
- **Сумнівне чи дуже зачіпне** (методика гармонізації, формат даних, `requirements.txt`,
  деплой) — спершу запитати людину, бо ця зміна вплине на всіх.

### Git
- У комітах і PR не згадувати AI — жодних `Co-Authored-By` від агента чи «Generated with …».
  Повідомлення лише про суть зміни, у стилі `git log` цього репо.
- Комітити й пушити — лише коли людина просить.

### Сервер і секрети
- Будь-який доступ до сервера деплою (`ssh`/`scp`/`docker exec`), навіть лише читання, —
  тільки після явного дозволу людини в чаті, щоразу окремо. Спершу покажи команду.
- `.env`, токени (зокрема FIRMS MAP_KEY), паролі не виводити в чат, не комітити, не вставляти
  в URL. Ключі — лише в `.streamlit/secrets.toml` (він у `.gitignore`).
- Великі файли даних не комітити: сирі CSV — у `data/raw/` (ігнорується git).

### Як працювати
- **Мова** — українська: спілкування, коментарі, документація, тексти інтерфейсу.
- **Код**: нові функції обробки — у `firecal/`, а не в `app.py`. До кожної — тест у `tests/`.
- **Коментарі** — детальні, українською, щоб Toksa і Макс (базовий Python) розуміли кожен
  крок: що робить рядок pandas/Streamlit і НАВІЩО. Неочевидні методи (groupby, transform,
  pivot_table, where, reindex) пояснювати на місці.
- **Windows**: у Git Bash heredoc із кирилицею псується — правити файли інструментом
  редагування, а не `sed` чи `python -` з heredoc. Вивід Python із кирилицею — з
  `PYTHONIOENCODING=utf-8`. Повідомлення коміту — через файл (`git commit -F`).
- **Перевіряти самому до «готово»**: поведінку, а не лише запуск. Обов'язково
  `pytest -q` і `python scripts/smoke_app.py`. UI — у браузері (`streamlit run app.py`)
  кліками по самому сценарію: консоль без помилок, вузький екран, темна й світла тема.
  У звіті чесно: що перевірено, а що ні.

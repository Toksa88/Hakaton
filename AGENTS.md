# AGENTS.md — інструкції для Claude / AI-асистентів

Читай цей файл перед будь-якою роботою в репозиторії.

## Що ми робимо
Хакатон, тема **Harmonization of MODIS and VIIRS Hot Spots**. Дедлайн ~15.11.2026.
Веб-додаток, що узгоджує активні осередки пожеж MODIS і VIIRS (NASA FIRMS) у
**календар активності горіння** для вибраної зони інтересу: історичні патерни,
незвичайні умови (аномалії), критичні періоди. Користувачі — служби раннього
попередження, вчені, землекористувачі. Регіон за замовчуванням — Україна.

## Стек і структура
Python 3.11+, Streamlit (UI), pandas, plotly. Без окремої БД — дані з CSV, кеш у parquet.
```
app.py                 Streamlit-додаток (усі вкладки)
firecal/load.py        CSV FIRMS -> єдина схема (lat, lon, date, sensor, conf_class, ...)
firecal/harmonize.py   гармонізація: сітка -> пожежо-клітинко-дні -> union -> калібрування k
firecal/analytics.py   календар, норма, аномалії (робастний z), критичні періоди
firecal/export.py      файли для кнопок «Скачати»: CSV під український Excel і .xlsx з шапкою
firecal/mapgrid.py     карта: дні горіння клітинок -> плавна картинка + невидимі квадрати для підказок
firecal/regions.py     зони інтересу: області (сітка firecal/oblasts.npz), групи, прифронтові
firecal/words.py       слова й числа для людей: «осередки», «у 6,8 раза більше», сезони, світлофор
.streamlit/config.toml тема (кольори для світлої і темної), шрифт, toolbarMode
scripts/               генератор тестових даних, smoke-тест додатку
tests/                 pytest
data/raw/              сирі CSV (не в git)
```

## Методика (не ламай без обговорення)
1. Достовірність: MODIS <30 low, 30–79 nominal, ≥80 high; VIIRS l/n/h. Лишаємо `type == 0`.
2. Точки -> клітинки сітки (дефолт 0.1°). Одиниця — пожежо-клітинко-день.
3. Union MODIS ∪ VIIRS для періоду з VIIRS.
4. До VIIRS (до 2012): MODIS × k[місяць], k = union/MODIS у період перекриття.

## Правила роботи для AI-агентів

Цей файл лежить у git навмисно: над проєктом працюють кілька людей з різних комп'ютерів,
і правила мусять їхати разом із кодом. Прочитай його першим, перш ніж щось міняти.

**Хто вирішує.** «Людина» нижче — той, хто зараз веде сесію з агентом. Дозвіл, даний
однією людиною, не поширюється на інших, на інші задачі чи на наступну сесію.

### Спільна робота
- **Перед роботою — `git pull`** і погляд на `git status`: хтось міг змінити ту саму частину.
- **Робота — у своїй гілці**, не в `master`. Назва гілки — про суть задачі.
- **У `master` — лише через PR.** Злиття вирішує людина (або рецензент за правилами команди),
  агент сам не мерджить. Маленькі PR, щоб не конфліктувати.
- **Чужі зміни не чіпати**: не відкочувати, не переписувати й не «прибирати» чужий код
  без прохання людини. Конфлікт при злитті — показати людині, а не розв'язувати навмання.
- **Без `push --force`** у спільні гілки, без переписування історії, яку вже хтось стягнув.
- **Сумнівне чи дуже зачіпне** (методика гармонізації, формат даних, `requirements.txt`,
  деплой) — спершу запитати людину, бо ця зміна вплине на всіх.

### Git
- У комітах і PR не згадувати AI — жодних `Co-Authored-By` від агента чи «Generated with …».
  Повідомлення лише про суть зміни, у стилі `git log` цього репо.
- Комітити й пушити — лише коли людина просить.

### Сервер і секрети
- Будь-який доступ до сервера деплою (`ssh`/`scp`/`docker exec`), навіть лише читання, —
  тільки після явного дозволу людини в чаті, щоразу окремо. Спершу покажи команду.
- `.env`, токени (зокрема FIRMS MAP_KEY), паролі не виводити в чат, не комітити, не вставляти
  в URL. Ключі — лише в `.streamlit/secrets.toml` (він у `.gitignore`).
- Великі файли даних не комітити: сирі CSV — у `data/raw/` (ігнорується git).

### Як працювати
- **Мова** — українська: спілкування, коментарі, документація, тексти інтерфейсу.
- **Код**: нові функції обробки — у `firecal/`, а не в `app.py`. До кожної — тест у `tests/`.
- **Коментарі** — детальні, українською, щоб Toksa і Макс (базовий Python) розуміли кожен
  крок: що робить рядок pandas/Streamlit і НАВІЩО. Неочевидні методи (groupby, transform,
  pivot_table, where, reindex) пояснювати на місці.
- **Windows**: у Git Bash heredoc із кирилицею псується — правити файли інструментом
  редагування, а не `sed` чи `python -` з heredoc. Вивід Python із кирилицею — з
  `PYTHONIOENCODING=utf-8`. Повідомлення коміту — через файл (`git commit -F`).
- **Перевіряти самому до «готово»**: поведінку, а не лише запуск. Обов'язково
  `pytest -q` і `python scripts/smoke_app.py`. UI — у браузері (`streamlit run app.py`)
  кліками по самому сценарію: консоль без помилок, вузький екран, темна й світла тема.
  У звіті чесно: що перевірено, а що ні.

### Пам'ятка для наступного агента
Після кожної змістовної зміни онови цей файл у тому ж коміті: нове правило чи інваріант,
пастка, на яку наступив, рішення команди і чому, крок, що лишився за людиною. Коротко,
без переказу коду й історії git. Застаріле — виправ або прибери одразу.
Секретів і особистих даних сюди не писати: файл бачать усі, хто має доступ до репо.

Поточні нотатки:
- Справжні дані: `scripts/download_firms.py` (MODIS 2000–2025 + VIIRS 2012–2025 по Україні,
  ~145 МБ, ~1,9 млн точок). З локальних машин FIRMS доступний, із хмарних сесій Claude — ні.
  Синтетика (`scripts/make_sample_data.py`) — лише для тестів без інтернету.
- На справжніх даних конвеєр швидкий (завантаження ~2 с, з кешу 0,1 с; розрахунок ~1 с).
- 2000 рік у даних неповний (MODIS лише з листопада), тож слайдер за замовчуванням з 2001
  (`analytics.default_years` відкидає неповні роки на краях).
- 2022+ на сході/півдні багато хот-спотів від бойових дій, а не с/г пожеж (67% точок з 24.02.2022 —
  у `regions.FRONTLINE`). У UI є перемикач, що їх викидає. Список FRONTLINE (7 областей) обрав агент,
  команда ще не підтвердила.
- Області: `firecal/oblasts.npz` — сітка 0.01° з номерами областей (`scripts/build_oblasts.py`,
  джерело geoBoundaries). Область точки = погляд у сітку, без shapely/geopandas. Колонку `oblast`
  додає `app.get_points`; `filter_points` порахує сам, якщо її нема.
- Карта (`firecal/mapgrid.py`): сітку розмиваємо САМІ в градусах (numpy, без scipy) і кладемо PNG
  шаром `map_layers` (рядки рівномірно в Меркаторі); поверх — невидимі квадрати `choropleth_map`
  для підказки й шкали. НЕ повертати `density_map`: вона додає плями фіксованого радіуса в пікселях,
  і при віддаленні вся Україна червона. Суцільні кольорові квадрати власник відкинув — за 25 років
  горіла майже кожна з ~7,7 тис. клітинок, і вони вкривають усю країну; тому низ шкали прозорий
  (`FADE_SCALE`), верх — 99-й перцентиль. Підкладка потребує інтернету.
- На карті ДВА шари-картинки: згладжена до зуму `ZOOM_SWITCH` (8), різка (`sigma_cells=0.35`) — з нього.
  Різка бере `cap` від згладженої (`smooth_image(..., cap=...)`), інакше кольори стрибають при зумі.
  Обидві PNG щоразу їдуть у браузер: на клітинці 0.05° це ~2,7 МБ.
- Календар (`go.Heatmap`, бо лише він вміє `xgap/ygap`): верх кольору — 97-й перцентиль таблиці,
  `hoverongaps=False` (порожні неповні тижні без підказки). Роки в підписах — `years_label` («2020», а не «2020–2020»).
- Пастка: Streamlit при зміні файлів перезапускає `app.py`, але НЕ перечитує `firecal/*` —
  після правок у `firecal` перезапускай сервер, інакше `AttributeError` на нову функцію.
- Файли користувачів живуть лише в пам'яті (`get_points`, `cache_resource`, 3 набори), на диск не пишуться;
  ліміт `maxUploadSize = 30` МБ у `.streamlit/config.toml` — контейнер на VPS має 1 ГБ. Підказка «?» біля поля
  завантаження обіцяє людям саме це — міняєш поведінку, міняй і текст.
- Завантажені через сайт файли — лише через `load.read_upload`: `type="csv"` в `file_uploader` перевіряє
  тільки розширення. Битий файл -> `BadFileError` з текстом для людини (`st.error`), добрі файли
  працюють далі. Файли в `data/raw/` так НЕ перевіряються — битий CSV там і досі валить додаток.
- Запасні значення в `normalize` — стовпчик (`zero`), не число: `to_numeric(0)` повертає число без
  `.fillna`, і CSV без `type`/`acq_time` падав.
- Дані за один рік (типовий річний файл FIRMS): слайдер «Роки» не малюємо — `st.slider` з min == max
  падає. Осі з роками — `type="category"`, інакше при 1–2 роках plotly пише «2 019,6».
- Порожній результат на вкладці — `st.info` в `if/else`, НЕ `st.stop()`: він обриває й наступні вкладки.
  Виняток — ДО вкладок: коли після фільтрів 0 точок або координати «від ≥ до», показуємо одне
  повідомлення і `st.stop()`. Інакше раннє попередження бреше зеленим «🟢 низький» там, де даних просто нема.
- Зона «Свої координати» (`CUSTOM_ZONE`, колишній «Свій прямокутник»): межі ±180/±90 і «від < до»
  перевіряємо САМІ (список `problems`, `st.error` українською). НЕ `min_value/max_value` у `number_input`:
  тоді Streamlit пише англійське «Number is outside the allowed range». Без перевірки 10-значне число
  відправляло центр карти в нікуди і браузер зависав. Карту центруємо на точках, що потрапили в зону.
- Календар: номер тижня в підказці — з `customdata`, НЕ `%{x}` (на осі підписи-місяці, `%{x}` дає «Лип»).
  Лінії-орієнтири під мишею — `showspikes` на обох осях.
- Шкали кольорів (календар, карта) і легенди — горизонтально ПІД графіком: `yref="container", y=0` +
  нижній `margin.b`. Вертикальна шкала праворуч на телефоні забирала пів ширини; легенда з `y=-0.15`
  накривала підписи років. У шкали `len=0.8` + `ticklabeloverflow="allow"`, інакше крайній підпис зникає.
- Шкала «мало → багато» — `HEAT_SCALE` (YlOrRd без майже білого `#ffffcc`), не рядок `"YlOrRd"`.
  Світла тема — бежева (`#f3ece2`), не біла: власник скаржився, що біле «виїдає» очі.
- Кнопка «Скинути налаштування»: віджети бічної панелі беруть значення з `SIDEBAR_DEFAULTS` через
  `session_state` (без `value=`), кнопка записує їх явно. НЕ `session_state.clear()`: Python скидається,
  а віджет на екрані — ні. Віджети на вкладках мають `key=tab_key(...)` з номером скидання.
  Новий віджет у бічній панелі — додай у `SIDEBAR_DEFAULTS` і дай йому `lang_key` (див. «Пастка мови»).
  У `AppTest` ключі віджетів бічної панелі — з мовою: `at.selectbox(key="zone_Українська")`.
- Меню ⋮ Streamlit англійською: «Record screen» ховаємо CSS, а «System/Light/Dark/Print» підміняємо
  через `::after` (за `data-testid`). Після оновлення Streamlit перевір, що testid не змінились.
  Вкладки в цій версії — `div[data-baseweb="tab"]`, не `button`.
- Заголовки plotly не переносяться — довгі обрізались на телефоні. Коротка назва + `subtitle_text`
  (`title=dict(text=..., subtitle_text=...)`), верхній відступ `t=70`.
- **Дві мови інтерфейсу (рішення власника 15.11):** перемикач «Українська / English» угорі бічної панелі,
  `st.session_state["lang"]` (окремо для кожного відвідувача — НЕ глобальна змінна модуля). Кожен текст

- **Інваріант:** k рахується на ВСІХ роках даних зони (`harmonize.run_pipeline`), слайдер років
  лише обрізає показ. Значення року не має залежати від слайдера — це стереже тест
  `test_slider_years_do_not_change_k`. Не переносити фільтр років до розрахунку k.
- Тижні — НЕ ISO, а від 1 січня (`analytics.week_of_year`): 52 на рік, дні 365–366 у 52-му.

  Дату тижня брати з `analytics.week_start`, не з `fromisocalendar`.
- **Інваріант:** денний ряд іде від першого до ОСТАННЬОГО дня даних (`run_pipeline`, `full_start/full_end`),
  НЕ до 31 грудня — інакше неіснуючі дні стають нулями і раннє попередження бреше «0 пожеж».
  `analytics.weekly` лишає лише повні тижні (обрізаний краєм даних тиждень — не «тихий тиждень»).
- Вікна по роках (`analytics.window_sums`): рік у індексі = рік дати `end`; для «наступних N днів» —
  `shift=N`, а не `end + N` (інакше на межі року в «історію» потрапляє майбутнє самої дати).

- **Мова інтерфейсу (рішення власника, редизайн для журі/оператора):** на екрані без наукових термінів.
  Одиниця — «осередок горіння» (= пожежо-клітинко-день), «зазвичай» (= медіана), «незвично гарячий»
  (= робастний z ≥ 2), «у 9 з 10 років нижче» (= p90), достовірність «низька/середня/висока». Терміни —
  лише в «Як це пораховано?», підказках «?» і словничку «Методики». Слова й формат чисел — через
  `firecal/words.py`, не f-рядками з `:,` (дає американське «12,345»). На кожній вкладці — `how_to_read`.

  скрипти команди). Тому в «Аномаліях» дві таблиці: `table` (CSV) і `table_ui` (екран і Excel).

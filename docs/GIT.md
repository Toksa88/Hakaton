# Шпаргалка по Git — для тих, хто бачить його вперше

Коротко: **Git** — це «історія збережень» проєкту на твоєму комп'ютері.
**GitHub** — сайт, де лежить спільна копія цієї історії для всієї команди
(наш репо: `https://github.com/Toksa88/Hakaton`).

Ти працюєш у себе → зберігаєш зміни (коміт) → відправляєш на GitHub (push) →
просиш команду глянути (Pull Request) → після «ок» зміни потрапляють у `master`.

Усі команди нижче пишемо в терміналі (PowerShell або термінал у VS Code),
перебуваючи в папці проєкту.

---

## 0. Словничок (5 слів, які треба знати)

| Слово | Що це по-людськи |
|---|---|
| **репозиторій (репо)** | Папка проєкту разом з усією історією змін |
| **коміт** | Один «знімок» змін з підписом, що зроблено. Як збереження в грі |
| **гілка (branch)** | Окрема лінія роботи. `master` — головна, «чиста» версія. Свою задачу робиш у своїй гілці, щоб не заважати іншим |
| **push / pull** | Відправити свої коміти на GitHub / забрати чужі з GitHub |
| **Pull Request (PR)** | Запит на GitHub: «ось мої зміни, гляньте й злийте в `master`» |

---

## 1. Один раз: встановити й налаштувати

1. Завантаж Git: <https://git-scm.com/download/win> → встановлюй, тицяючи «Next» (усе за замовчуванням ок).
2. Зареєструйся на <https://github.com> і скажи Toksa свій нік — він додасть тебе в репо.
3. Відкрий **новий** термінал і представся Git'у (ім'я й пошта підписуватимуть твої коміти):

```powershell
git config --global user.name "Твоє Ім'я"
git config --global user.email "пошта@з-github.com"
```

4. Скачай проєкт собі (зробить папку `Hakaton`):

```powershell
cd D:\               # куди хочеш покласти проєкт
git clone https://github.com/Toksa88/Hakaton.git
cd Hakaton
```

Під час першого `push` Windows відкриє вікно входу в GitHub — просто залогінься в браузері.

Далі — налаштування Python за `docs/NOVACHKAM.md`.

## 2. Щоразу, коли сідаєш працювати (головний цикл)

```powershell
# 1) Перейти на master і забрати свіже від команди
git switch master
git pull

# 2) Створити СВОЮ гілку для задачі (назва — про суть, латиницею, через дефіс)
git switch -c dodaty-test-kalendaria

# 3) ... працюєш: правиш файли, запускаєш, перевіряєш ...

# 4) Подивитися, що змінилося
git status          # які файли змінені
git diff            # що саме змінено всередині (вихід — клавіша q)

# 5) Позначити файли для коміту
git add tests/test_calendar.py     # конкретний файл
# або всі змінені разом:
git add .

# 6) Зберегти знімок з описом (українською, що зроблено)
git commit -m "Тест: календар не має пропущених тижнів"

# 7) Відправити гілку на GitHub
git push -u origin dodaty-test-kalendaria   # перший раз для цієї гілки
git push                                     # наступні рази — просто так
```

Комітити можна скільки завгодно разів — маленькими кроками навіть краще.

---

## 3. Pull Request (PR) на GitHub

1. Після `push` відкрий <https://github.com/Toksa88/Hakaton> — зверху буде жовта плашка
   **«Compare & pull request»**. Тисни.
2. Напиши заголовок і пару речень: що зробив і як перевірив.
3. **Create pull request**. Скинь посилання в чат команди.
4. Хтось дивиться, може залишити коментарі. Виправляєш у **тій самій гілці** →
   `git add` → `git commit` → `git push` — PR оновиться сам.
5. Коли все ок — тиснуть **Merge**. Твої зміни в `master` 🎉
6. Після злиття повертаєшся до кроку 2 з новою гілкою для нової задачі.

## 4. Мою гілку треба оновити — в `master` з'явилось нове

```powershell
git switch master
git pull
git switch моя-гілка
git merge master
```

Якщо Git написав **CONFLICT** — див. наступний пункт.

## 5. Конфлікт — не панікуй

Конфлікт = ти й хтось інший змінили **ті самі рядки** одного файлу. Git не знає, чия версія правильна.

У файлі з'являться такі мітки:

```
<<<<<<< HEAD
мій варіант рядка
=======
варіант з master
>>>>>>> master
```

Що робити:
1. Відкрий файл (VS Code підсвічує конфлікт і дає кнопки *Accept Current / Incoming / Both*).
2. Залиш правильний варіант, **видали всі мітки** `<<<<<<<`, `=======`, `>>>>>>>`.
3. Збережи файл, потім:

```powershell
git add назва-файлу
git commit -m "Злиття master у мою гілку"
```

Не розумієш, яку версію лишати, — **питай автора тих рядків або Toksa**, не вгадуй.
Передумав зливати взагалі: `git merge --abort` — все повернеться як було.

## 6. «Ой» — типові халепи

| Ситуація | Що робити |
|---|---|
| Зіпсував файл і хочу повернути як в останньому коміті | `git restore назва-файлу` ⚠️ твої незбережені зміни в ньому зникнуть |
| Зробив `git add` не того файлу | `git restore --staged назва-файлу` (зміни в файлі лишаються) |
| Опечатка в повідомленні останнього коміту (ще НЕ пушив) | `git commit --amend -m "Нормальний текст"` |
| Почав працювати прямо в `master` (ще не комітив) | `git switch -c нова-гілка` — зміни переїдуть у нову гілку |
| Закомітив у `master` (ще не пушив) | Напиши Toksa — виправимо разом |
| `git push` пише *rejected* / *fetch first* | Хтось уже пушив у цю гілку: `git pull`, потім знову `git push` |
| `git pull` пише, що є незбережені зміни | Спершу закоміть (`git add .` + `git commit -m "..."`), потім `git pull` |
| Відкрився дивний редактор (Vim) після `git commit` / `git merge` | Набери `:wq` і Enter — це «зберегти й вийти» |
| `git log` / `git diff` «завис» | Це прокрутка, вихід — клавіша `q` |
| Взагалі не розумію, що відбувається | `git status` — він майже завжди підказує наступну команду. Або скопіюй вивід Claude/в чат |

## 7. Правила нашої команди

- ✅ Перед роботою — `git pull`.
- ✅ Кожна задача — своя гілка. У `master` лише через PR.
- ✅ Маленькі PR (одна задача — один PR): легше дивитись, менше конфліктів.
- ✅ Перед PR — `pytest -q` (тести зелені).
- ❌ **Ніколи** не пиши напряму в `master`.
- ❌ **Ніколи** `git push --force` — можна стерти чужу роботу.
- ❌ Не комітити дані (`data/raw/*.csv` — завеликі, Git їх і так ігнорує),
  ключі й паролі (FIRMS MAP_KEY живе лише в `.streamlit/secrets.toml`).
- ❌ Не «прибирати» чужий код без питання автора.

## 8. Корисні, але необов'язкові

```powershell
git log --oneline -10      # останні 10 комітів коротко
git branch                 # мої гілки (зірочка — де я зараз)
git branch -a              # разом з гілками на GitHub
git switch назва-гілки     # перейти на існуючу гілку
git branch -d стара-гілка  # видалити свою гілку, яку вже злили
```

У VS Code є вкладка **Source Control** (значок гілочки зліва) — там те саме кнопками:
галочки для `add`, поле для повідомлення коміту, кнопка **Sync** для `pull` + `push`.
Але спершу краще зрозуміти команди вище — тоді кнопки не лякатимуть.

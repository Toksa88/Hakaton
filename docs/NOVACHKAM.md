## 1. Що ми робимо (без жодного коду)

Над Землею літають супутники. Вони «фотографують» планету в інфрачервоному світлі й
помічають гарячі місця — пожежі. Кожне таке місце — це **точка**: широта, довгота, дата.
NASA викладає ці точки на сайті **FIRMS** у CSV-файлах (CSV — це таблиця Excel у вигляді тексту).

Точки знімають два «фотоапарати»:

| Датчик | Працює з | «Зір» |
|---|---|---|
| **MODIS** | 2000 р. | гірший: піксель ~1 км |
| **VIIRS** | 2012 р. | кращий: піксель ~375 м |

**Проблема.** Новий VIIRS на ту саму пожежу ставить не 1 точку, а 10. Якщо просто рахувати
точки, вийде, ніби з 2012 року пожеж стало в рази більше. Насправді просто змінився фотоапарат.

**Наше завдання** — рахувати пожежі чесно, щоб 2005 і 2020 роки можна було порівнювати,
і показати результат як **календар**: коли в році горить найбільше, які роки були незвичайні.

## 3. Весь проєкт на прикладі з 5 точок

Припустимо, за 1 квітня в нас є 5 точок:

```
датчик  широта  довгота
VIIRS   50.01   30.01
VIIRS   50.02   30.01
VIIRS   50.03   30.02
MODIS   50.02   30.02
VIIRS   48.50   35.70
```

### Крок 1 — `firecal/load.py` («перекладач»)
Файли MODIS і VIIRS різні: колонки названі по-різному, достовірність у MODIS — число 0–100,
а у VIIRS — літера `l`/`n`/`h`. Цей файл перетворює обидва формати на **однакову таблицю**
(як на прикладі вище) і зводить достовірність до трьох слів: `low` / `nominal` / `high`.

### Крок 2 — `firecal/harmonize.py` («чесний підрахунок»)
1. **Ділимо карту на квадратики**, як зошит у клітинку. Квадратик ≈ 10×10 км (0.1 градуса).
2. Питаємо не «скільки точок?», а **«чи горів цей квадратик цього дня?»**.
   - Перші 4 точки — в одному квадратику → **1 пожежа**.
   - Остання — в іншому → ще **1 пожежа**.
   - Разом **2**, а не 5. «Зайві» точки VIIRS більше нічого не псують.

   Така одиниця в коді називається **пожежо-клітинко-день**.
3. **До 2012 року був лише MODIS**, а він частину пожеж пропускав. Беремо роки, коли працювали
   обидва датчики, і дивимось, наприклад: «у квітні MODIS бачить лише половину пожеж».
   Тоді квітень 2005 року множимо на 2. Це число в коді — **`k`** (окреме для кожного місяця).

Результат кроку 2 — **один ряд чисел: скільки пожеж було кожного дня** з 2003 року.

### Крок 3 — `firecal/analytics.py` («висновки»)
З цього ряду рахуємо:
- **Календар** — таблиця «рік × тиждень року». Темніша клітинка = більше пожеж.
- **Норма** — скільки зазвичай горить у цей тиждень року (медіана по всіх роках).
- **Аномалії** — тижні, коли горіло набагато більше чи менше за норму.
- **Критичні періоди** — 25% найнебезпечніших тижнів року (сезон пожеж).

### Крок 4 — `app.py` («вітрина», сайт)
Сайт на бібліотеці **Streamlit**. Він бере результати кроків 1–3 і малює графіки та вкладки.
Головне, що треба знати: **коли ви натискаєте будь-що на сайті, весь `app.py` виконується
заново згори донизу.** `st.щось(...)` — це «намалюй на сторінці щось». Більше магії немає.

### Решта файлів

| Файл | Навіщо |
|---|---|
| `firecal/regions.py` | Зони для вибору на сайті: справжні області (межі з `firecal/oblasts.npz`) і їх групи |
| `scripts/make_sample_data.py` | Генерує **вигадані** дані, поки немає справжніх |
| `scripts/smoke_app.py` | Перевірка «сайт запускається без помилок» |
| `tests/test_pipeline.py` | Перевірки, що код рахує правильно |
| `data/raw/` | Сюди кладемо CSV з FIRMS (у git не потрапляють — завеликі) |
| `requirements.txt` | Список бібліотек, які треба встановити |
| `AGENTS.md` | Правила проєкту (для людей і для Claude) |

```
CSV з FIRMS ──load.py──▶ однакові таблиці ──harmonize.py──▶ пожежі по днях ──analytics.py──▶ календар, норма, аномалії
                                                                                          ▲
                                                                          app.py малює це на сайті
```

## 4. Як запустити в себе (Windows)

Потрібен Python 3.11 або новіший (https://www.python.org, при встановленні поставити галочку
**Add Python to PATH**). Відкрийте папку проєкту у VS Code → меню Terminal → New Terminal.
Команди вводимо **по одній**:

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python scripts/make_sample_data.py
streamlit run app.py
```

Що робить кожна:
1. `python -m venv .venv` — створює «пісочницю» `.venv` для бібліотек саме цього проєкту (один раз).
2. `.venv\Scripts\activate` — заходимо в пісочницю. На початку рядка з'явиться `(.venv)`.
   Робити **щоразу**, коли відкриваєте новий термінал.
3. `pip install -r requirements.txt` — встановлює бібліотеки (один раз, кілька хвилин).
4. `python scripts/make_sample_data.py` — створює тестові дані (один раз).
5. `streamlit run app.py` — запускає сайт; відкриється браузер. Зупинити — `Ctrl+C` у терміналі.

Покрутіть повзунки зліва й подивіться, що змінюється, — так розібратися найшвидше.

### Перевірки перед тим, як казати «готово»
```
pytest -q
python scripts/smoke_app.py
```
Має бути `5 passed` (або більше, якщо додали тести) і `OK, вкладок: 6`.

### Якщо щось не працює
| Помилка | Що робити |
|---|---|
| `...activate cannot be loaded because running scripts is disabled` | Один раз виконати `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, відповісти `Y` |
| `No module named streamlit` (або pandas, pytest) | Ви не в пісочниці: виконайте `.venv\Scripts\activate` |
| `'python' is not recognized` | Python не встановлено або не стоїть галочка «Add to PATH» — перевстановити |
| На сайті «Немає даних» | Запустіть `python scripts/make_sample_data.py` або покладіть CSV у `data/raw/` |
| Карта порожня | Карті потрібен інтернет для підкладки |
| Кракозябри замість кирилиці в терміналі | Перед командою: `$env:PYTHONIOENCODING="utf-8"` |

## 5. Git за 2 хвилини

Git — це «історія збережень» проєкту, спільна для всієї команди. GitHub — сайт, де вона лежить.

| Команда | Що робить |
|---|---|
| `git pull` | Забрати свіжі зміни команди. **Робити перед початком роботи** |
| `git status` | Що я змінив |
| `git switch -c назва-задачі` | Створити свою гілку (окрему «копію» для своєї задачі) |
| `git add файл` | Позначити файл для збереження |
| `git commit -m "що зробив"` | Зберегти знімок змін |
| `git push` | Відправити свою гілку на GitHub |

Правило команди: **у `master` напряму не пишемо.** Робимо свою гілку → `push` → на GitHub
відкриваємо Pull Request (PR) → хтось дивиться → тоді зливаємо.
